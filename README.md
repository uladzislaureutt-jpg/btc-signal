# BTC Technical Signal Engine · Core 0.2.0a1

Shadow-инструмент для BTCUSDT: **1D regime → 4H level zone → 1H confirmation → score → Telegram**.

Это исследовательская система, а не финансовая рекомендация. Она не подключается к торговому аккаунту и не исполняет ордера.

## Что уже реализовано

- Binance Spot OHLCV без API-ключа, затем Bybit Spot и Binance.US как fallback;
- все три таймфрейма одного расчёта всегда берутся с одной и той же биржи;
- исключение незакрытой свечи;
- EMA 50/200, RSI, ATR, относительный объём;
- 4H swing-зоны с ATR-шириной и оценкой качества;
- 1D режим, 4H структура, 1H реакция цены;
- score 0–90 и hard veto;
- состояния `neutral`, `watch`, `signal`, `strong_signal`;
- Telegram, защита от повторной отправки;
- cooldown между сигналами и запрет перекрывающихся виртуальных сделок;
- локальный SQLite или Supabase;
- исторический backtest с входом на открытии следующей 1H-свечи, комиссиями, проскальзыванием, gap-execution и консервативным правилом внутри свечи;
- диагностическая воронка по каждому проверенному часу: veto, score, расстояние до зоны, блокировки и изолированные контрфактические исходы;
- HTTP endpoint для Supabase Cron/внешнего cron;
- GitHub Actions: тесты и резервный почасовой shadow-run.

## Быстрый локальный запуск

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.lock
pip install --no-deps -e .
pytest -q
btc-signal live --dry-run
```

Backtest:

```bash
btc-signal backtest --days 240
```

Результаты сделок появятся в `reports/backtest_trades.csv`, сводка — в терминале. Дополнительно создаются `backtest_diagnostics.json` с воронкой решений и `backtest_manifest.json` с версией, commit SHA и хешами данных, конфигурации и сделок.

На GitHub backtest запускается вручную: **Actions → BTC historical backtest → Run workflow**. GitHub загрузит историю с учётом отдельного 210-дневного прогрева индикаторов и сохранит CSV, JSON-сводку и использованные 1H-свечи в артефакте запуска.

## Telegram и Supabase

1. Скопируйте `.env.example` в `.env` и заполните переменные в среде запуска.
2. Выполните SQL из `supabase/migrations/0001_btc_signal.sql` в SQL Editor.
3. Для серверного worker используйте `SUPABASE_SECRET_KEY=sb_secret_...`. Legacy service-role key тоже поддерживается, но Supabase выводит его из основного употребления. Не помещайте любой из этих ключей в браузерный код.
4. Запустите `btc-signal live`. Если Supabase-переменные не заданы, автоматически используется локальный SQLite.

## Основной режим размещения

Соберите Docker-образ и разместите его на Render/Railway/Fly.io или другом сервисе, который принимает Dockerfile. Команда уже задана:

```text
uvicorn btc_signal.api:app --host 0.0.0.0 --port 8000
```

Проверка: `GET /health`.

Планировщик должен выполнять `POST /run` с заголовком:

```text
X-Cron-Secret: значение CRON_SECRET
```

Для стратегии с 1H-триггером достаточно запуска на 5–10-й минуте каждого часа. В Supabase Cron это можно настроить через Dashboard → Integrations → Cron → HTTP request. Резервный workflow `.github/workflows/shadow.yml` запускается в 07 минут каждого часа.

## Логика score

| Блок | Максимум |
|---|---:|
| Качество уровня | 30 |
| 1D regime | 20 |
| 4H structure | 15 |
| 1H price action | 15 |
| Volume | 0 |
| RSI momentum | 5 |
| ATR volatility | 5 |

Пороги по умолчанию: WATCH 65, SIGNAL 75, STRONG 85. Все параметры находятся в `config/strategy.yaml`.

Hard veto блокирует сигнал, если нет качественной 4H-зоны, направление конфликтует с 1D, R/R ниже 1.8 или цена уже ушла от зоны.

Core 0.1.2 также требует фактическую реакцию цены на 1H, ограничивает стоимость сделки величиной 0.60R, отсекает насыщенные уровни качества 10/10 и всплеск объёма, который для контртрендового входа у уровня чаще соответствует риску пробоя.

## Правильный порядок проверки

1. Запустить unit-тесты.
2. Выполнить backtest минимум на 240 днях.
3. Проверить распределение сделок по режимам рынка, а не только общий win rate.
4. Включить shadow Telegram минимум на 4–8 недель.
5. Не подключать исполнение ордеров, пока выборка не станет статистически полезной и положительная expectancy не сохранится вне периода настройки.

## Важные ограничения Core 0.2.0a1

- Уровни строятся алгоритмически и требуют калибровки на реальных данных.
- Резервные биржи могут иметь немного другие свечи и объёмы; имя фактического источника записывается в каждый сигнал.
- Backtest работает по 1H OHLCV: если стоп и цель затронуты одной свечой, засчитывается стоп.
- Незавершённые 4H/1D агрегаты не участвуют в backtest, чтобы не было скрытого look-ahead/repainting.
- Funding, open interest, ликвидации и стакан пока не используются.
- Целевые 1–3 сделки в сутки не гарантируются: частоту нельзя повышать ценой качества. Фактическую частоту покажет backtest/shadow-журнал.
- Для серьёзной оценки нужен walk-forward/out-of-sample анализ; он запланирован для Core 0.2.

## Decision Funnel · Core 0.1.3

Версия 0.1.3 не меняет торговые фильтры. Она измеряет все часы backtest, включая часы с открытой виртуальной позицией, считает отдельные и совместные veto, распределение score, расстояние до ближайшей зоны в ATR и результат кандидатов с единственным блокирующим условием. Контрфактические сделки могут перекрываться и не являются портфельным результатом.

## Реалистичность backtest · Core 0.1.4

Сигнал рассчитывается только после закрытия 1H-свечи, а виртуальный вход выполняется по открытию следующей свечи. R/R и стоимость риска повторно проверяются по фактической цене входа. Гэп через стоп исполняется по цене открытия, а при касании стопа и цели внутри одной свечи первым считается стоп. Неполные 4H/1D-агрегаты исключаются. `backtest_manifest.json` и сводка содержат аудит пропусков, дубликатов, OHLC, длительности свечей и часового пояса. Funding не применяется, поскольку источник и модель сделки относятся к spot.

Текущие rolling-уровни дня/недели сохранены без изменения торговой логики. Календарные UTC-уровни проверяются отдельно на этапе расширения источников уровней.

## Проверка устойчивости · Core 0.1.5

Backtest публикует результаты по годам и кварталам, 95%-е интервалы moving-block bootstrap и фиксированные rolling walk-forward окна 180/90 дней. Bootstrap использует фиксированный seed и блоки сделок, чтобы результат был воспроизводимым и не разрушал полностью серийную зависимость. Fixed walk-forward не выбирает параметры на train-окне. Sensitivity реализован в Core 0.1.6; tuning не выполняется, пока проверяемая область параметров не показывает устойчивую положительную expectancy. Push-trigger версии 0.1.5 запускает 1000 дней оценки плюс отдельный 210-дневный прогрев.

## Sensitivity-анализ · Core 0.1.6

Индикаторы 1H/4H/1D предварительно рассчитываются один раз причинным способом. Затем расширенный decision tape строится для общей оболочки параметров и девять уникальных one-at-a-time сценариев воспроизводятся с теми же правилами выбора кандидата, позиции, cooldown и исполнения на следующем open.

Проверяются `min_score = 70/75/80`, `min_rr = 1.6/1.8/2.0`, `max_distance_atr = 0.8/1.0/1.2` и `max_cost_r = 0.5/0.6/0.7`. CI сравнивает baseline replay с обычным backtest по числу сделок, total/gross/cost R, profit factor и drawdown с допуском `1e-9`; расхождение останавливает workflow.

На 1000-дневной контрольной выборке все 9 сценариев дали отрицательную expectancy, поэтому production-конфигурация не изменена и tuning walk-forward намеренно не запускался.


## Замороженный trend-long holdout · Core 0.2.0a1

Исследовательская ветка добавляет отдельный long-only движок продолжения тренда, не изменяя прежний level-first shadow-сигнал. Первичная спецификация зафиксирована до просмотра holdout 2020–2023: закрытие 4H выше максимума предыдущих 20 баров, цена выше растущей EMA200, начальный стоп 2 ATR(4H), активация трейлинга после +1 ATR, трейлинг 3 ATR и максимум 60 дней.

Сигнал использует только завершённый 4H-бар, вход выполняется на точном следующем 1H open, а новый трейлинг начинает действовать только со следующего часа. Требование risk/cost >= 8 проверяется по фактической цене входа. Новые входы разрешены с 2020-01-01 до 2024-01-01; данные 2019 года используются только для прогрева, а январь–март 2024 — только для закрытия уже открытых позиций.

Данные загружаются из официальных месячных Binance Spot архивов; SHA-256 каждого ZIP сверяется с .CHECKSUM. Основной round-trip cost равен 30 bps. Полная матрица 81 сценария проверяет breakout 15/20/30, stop 1.5/2.0/2.5 ATR, trail 2.5/3.0/4.0 ATR и costs 15/30/45 bps. Матрица описывает устойчивость и не выбирает новую конфигурацию по результату holdout.

Запуск: Actions → Frozen BTC trend holdout 2020-2023 → Run workflow или:

```bash
btc-signal trend-backtest
```

Артефакт содержит исходные 1H-свечи, сделки, подробную сводку, все 81 сценария и manifest с commit SHA и хешами файлов.
